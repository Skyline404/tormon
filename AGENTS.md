# TorrentMonitor - Кастомный форк (Skyline404)

Данный репозиторий является форком оригинального проекта [ElizarovEugene/TorrentMonitor](https://github.com/ElizarovEugene/TorrentMonitor). Он содержит ряд улучшений и исправлений для работы в Docker-окружении, стабильного обхода Cloudflare (капчи) и корректной работы с современными версиями qBittorrent.

## Основные отличия от upstream (оригинала)

### 1. Docker-окружение и Инициализация
* **Автоконфигурация при чистой установке**: При первом запуске в пустой базе данных (через `docker-entrypoint.sh`), теперь автоматически проставляются настройки: интеграция с `qBittorrent` по умолчанию включена, прописывается адрес клиента `http://host.docker.internal:8090`, очищается глобальный путь закачки (`pathToDownload` остается пустым для корректной работы авто-категорий), и прописывается URL для `flaresolverr`.
* **Автонастройка**: Добавлен стартовый скрипт `docker-entrypoint.sh`. При первом запуске контейнера он автоматически инициализирует SQLite базу данных (`tormon.db` из дампа `tormon.sql`) и копирует дефолтный `config.php`, не требуя ручной настройки через volume.
* **Сетевая маршрутизация**: В `docker-compose.yml` по умолчанию задана привязка к внешней сети `media`. Это позволяет ТоррентМонитору общаться с другими приложениями (тем же `host.docker.internal:8090` - qBittorrent) без необходимости создавать единый compose-файл на все железо.
* **Интеграция с FlareSolverr**: В `docker-compose.yml` "из коробки" встроен сервис `flaresolverr`. Для базы данных ТоррентМонитора прописан параметр `flaresolverrUrl` = `http://flaresolverr:8191`. Это позволяет системе самой обрабатывать 403 и 503 HTTP-ответы от Cloudflare (особенно для сервера RuTracker) и корректно доставать страницы в браузере под капотом.

### 2. Интеграция с qBittorrent API v2 (v4.3+ / v5.x)
* **Метод `/start`**: Команда вывода торрента из паузы переведена с устаревшего метода `/api/v2/torrents/resume` на актуальный `/api/v2/torrents/start`.
* **Автоматическое снятие галочек со старых серий**: В `class/qBittorrent.class.php` исправлена логика API-запроса на получение списка файлов раздачи. Для метода `/api/v2/torrents/files` был заменен тип запроса с `POST` на `GET`. Это вернуло работоспособность функции приоритетов торрента — теперь при выходе новой серии клиент честно получает индекс старых серий и ставит им приоритет скачивания "0" (Do not download).
* **Защита от состояния гонки (Race Condition)**: Добавлен fallback для хэша торрента. Если qBittorrent не успевает мгновенно обработать скачанный `.torrent` и выдает пустой ответ на запрос хэша, скрипт использует временно старый хэш и не обваливает базу данных `tormon.db` (ошибка Integrity constraint null).

### 3. Трекеры и Авторизация
* **RuTracker (Авторизация по куки)**: В настройки UI (`include/credentials.php`) и движок `trackers/rutracker.org.engine.php` добавлено текстовое поле для ручного ввода куки `bb_session` (аналогично nnmclub). Спасает в ситуации, когда логин по паролю регулярно блокируется из-за CAPTCHA от Cloudflare, и нужно просто подкинуть рабочую сессию из браузера.
* **Проверка интернета**: В `class/System.class.php` системный URL для проверки наличия соединения изменен с `ya.ru` (поисковик периодически отдавал капчу Docker-IP серверам и имитировал для скрипта "отсутствие сети") на стабильный `example.com`.
* **NNM-Club**: Сохранен аналогичный кастомный механизм обхода капчи и авторизации по сессионным кукам `session_id`.
